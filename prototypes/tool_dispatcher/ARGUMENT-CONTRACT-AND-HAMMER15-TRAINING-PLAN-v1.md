# Yuki Typed Argument Contract and Hammer 1.5B Training Plan

Date: 2026-08-25

Status: **contract v1 implemented; training data not generated; no model run**

## Purpose

Yuki's experiments repeatedly showed that these are different tasks:

```text
semantic routing          exact payload transport
which tool?               which literal characters?
```

A model can solve one and fail the other. The deterministic binder already reached 95.1% literal-source accuracy on eligible frozen Hammer 7B cases, while uniform binding lowered the old official score because that gold sometimes expects semantic normalization.

The prototype now defines the transport contract before generating training data or spending the frozen 450 benchmark.

Machine-readable source of truth: `argument-contract-v1.json`

Contract identifier: `yuki-argument-contract-v1`

## Field contract for all 18 tools

| Tool | Field | Mode | Contract comparison | Reason |
|---|---|---|---|---|
| `time` | — | `no_argument` | Empty object | No user payload. |
| `weather` | `city` | `semantic_argument` | Normalized text | Extract the place from surrounding grammar; case/spacing are not meaningful. |
| `fetch` | `url` | `literal_source` | Character exact | A changed character can identify a different resource. |
| `search` | `query` | `literal_source` | Character exact | Search operators, punctuation, quotes, casing, and wording may affect results. |
| `calc` | `expression` | `semantic_argument` | Arithmetic AST | Whitespace/redundant parentheses may normalize; mathematical structure may not. |
| `hardware` | `metric` | `semantic_argument` | Canonical enum | Natural language maps to `cpu`, `ram`, `disk`, `process`, `top`, `gpu`, `temp`, or `all`. Omission is equivalent to `all`. |
| `see` | `target` | `semantic_argument` | Referent phrase | `my keys` and `keys` identify the same target. Omission means describe the scene. |
| `image` | `prompt` | `literal_source` | Character exact | Creative wording, quoted labels, styles, casing, and punctuation are user payload. |
| `read` | `filepath` | `literal_source` | Character exact | OS paths are character- and case-sensitive. |
| `shell` | `command` | `literal_source` | Character exact | Command syntax must never be regenerated by the binder. This does not authorize execution. |
| `yuki_write` | `filename_and_content` | `literal_source` | Exact filename + exact content, joined with `|` | Both components are exact-sensitive; the pipe is the only deterministic insertion. |
| `yuki_read` | `filename` | `literal_source` | Character exact | Managed-store filename identity matters. |
| `yuki_list` | — | `no_argument` | Empty object | No user payload. |
| `yuki_delete` | `filename` | `literal_source` | Character exact | Destructive target identity must be exact. |
| `yuki_append` | `filename_and_content` | `literal_source` | Exact filename + exact content, joined with `|` | Existing filename and appended bytes are exact-sensitive. |
| `remember` | `fact` | `semantic_argument` | Canonical/accepted semantic reference | A first-person statement may need conversion to a short standalone fact about the user. |
| `recall` | `topic` | `semantic_argument` | Referent phrase | Retrieval needs a compact topic, not the full memory question. |
| `ask_claude` | `question` | `literal_source` | Character exact | The external agent should receive the intended user-authored message without rewriting. |

Totals:

- 10 `literal_source` fields.
- 6 `semantic_argument` fields.
- 2 `no_argument` tools.

## Literal source-span policy

For every `literal_source` field:

1. Characters come only from the immutable raw user request.
2. No model output is a character source. Qwen/Hammer hints may rank candidates only.
3. Do not normalize case, Unicode, whitespace, punctuation, articles, spelling, quotes inside the payload, pronouns, paths, or operators.
4. Exclude surrounding request syntax such as “Search for”, “Ask Claude”, or “Read”.
5. Quotes/backticks used only as delimiters are excluded; everything inside them is preserved.
6. Terminal punctuation is included only when it belongs to the payload. If request punctuation and payload punctuation cannot be distinguished deterministically, annotate ambiguity and abstain.
7. For Yuki write/append, filename and content may be separate source spans. The binder may insert only the declared `|` separator.
8. Repeated or equally plausible spans are ambiguous. The binder abstains instead of guessing.
9. A literal benchmark value must come from an independent annotation. The scorer must never silently treat old semantic gold as a literal span.

## Semantic argument policy

`semantic_argument` does not mean “anything roughly related is correct.” It means the field has a deterministic canonicalization rule:

- `weather.city`: Unicode/case/whitespace normalization.
- `calc.expression`: same safely parsed arithmetic AST; no evaluation in the scorer.
- `hardware.metric`: exact canonical enum; omitted and `all` are equivalent.
- `see.target`: conservative referent normalization, currently leading articles/possessives plus case/spacing.
- `recall.topic`: the same conservative referent normalization.
- `remember.fact`: canonical gold or explicitly enumerated accepted alternatives. No embedding or model judge.

Nontrivial paraphrases require an explicit accepted alternative in the dataset. The scorer does not guess semantic equivalence with another LLM.

## What changed in the harness

### New machine-readable contract

`argument-contract-v1.json` is the prototype source of truth. `argument_contract.py` validates it and fails if its tools, parameter names, or requiredness drift from the live Yuki registry.

Production `tools/` metadata and implementations remain untouched.

### Separate contract scoring

The existing metrics remain unchanged:

- strict official arguments/exact calls;
- execution-equivalent arguments/exact calls;
- schema validity and malformed output.

New reports can additionally contain:

- `contract_scoring_coverage_rate`;
- `contract_argument_accuracy` on scoreable cases;
- `contract_exact_call_accuracy` on scoreable cases;
- per-case contract mode, comparator, reason, and accepted values.

For literal fields without an independent source annotation, contract correctness is `null`, not false and not silently copied from official gold.

### Immutable sidecar annotations

Literal and semantic alternatives may live in a separate JSON sidecar bound to the dataset SHA-256. The benchmark command refuses a sidecar whose contract version or dataset checksum differs.

This lets us add typed references later without editing `phase2-cases.json` or changing its checksum.

### Fine-tuning export guard

Benchmark failures now record whether they are eligible under the typed contract. A literal-field failure without an independent literal label is not automatically safe training material.

## Frozen 450 protection

The Phase 2 file remains immutable:

```text
phase2-cases.json
SHA-256: 5b26b9a493ccc58de7b606a829b14487251df3a068a0bcfd1f69c3ae1f966466
```

Rules before the final evaluation:

- Never copy frozen requests into training, validation, or hard-dev.
- Never use frozen model failures as example text. Failure *families* may guide coverage.
- Do not tune prompts, schema descriptions, binder grammar, or training hyperparameters from frozen results.
- Keep payload dictionaries and template families disjoint by split.
- Reject exact duplicates and high-overlap near-duplicates against the frozen 450 before training.
- Keep the final Hammer checkpoint and inference configuration fixed before opening the sacred benchmark.
- Run the frozen 450 once for the selected checkpoint unless a mechanical infrastructure failure invalidates the run.

## Hammer 1.5B Yuki dataset v1

Target initial size: **6,400 examples**, inside the approved 5k–8k range.

### Proposed composition

| Family | Examples | Purpose |
|---|---:|---|
| Balanced ordinary coverage | 1,800 | At least 100 independent intents per tool; clear and natural phrasing. |
| Ontology/confusion boundaries | 2,400 | `read↔yuki_read`, `write↔append`, `see↔image`, `search↔recall`, `search↔fetch`, `remember↔recall`, plus weather/hardware/calc controls. |
| Literal payload preservation | 1,400 | URLs, queries, image prompts, paths, commands, Yuki filenames/content, and Claude messages with punctuation, Unicode, code, quotes, case, and repeated tokens. |
| Valid rejection/impossible delegation | 300 | Only cases where none of the offered tools can perform the delegated action. Keep rejection rare to avoid recreating `see`/`recall` refusal behavior. |
| Adversarial schema/output discipline | 500 | Injection-like text inside payloads, multiple tool names, empty/missing arguments, and requests that mention a competing tool without intending it. |
| **Total** | **6,400** | |

### Split before generation

| Split | Examples | Use |
|---|---:|---|
| Train | 5,000 | LoRA/QLoRA gradient updates only. |
| Validation | 700 | Loss/early stopping and limited checkpoint selection. |
| Hard-dev | 700 | Final internal gate with unseen templates, payload dictionaries, and paraphrase families. Never train on it. |

The split must happen at the scenario/template/payload-family seed level before paraphrases are produced. Randomly splitting finished rows would leak near-duplicates.

### Schema exposure mix

Training should reflect the intended architecture without making Hammer helpless outside one perfect domain:

- 55% logical Yuki domain subsets.
- 25% explicit confusion-focused subsets.
- 15% all 18 schemas.
- 5% valid no-tool/rejection cases.

The model output remains Hammer's native single-call format. There is no chat response, explanation, tool result, self-correction, retry voting, or conversation history.

### Label construction

- Tool labels come from scenario definitions, not another model's guess.
- Literal arguments come from recorded source offsets/components and pass a reconstruction invariant.
- Semantic arguments use canonical values plus explicit accepted alternatives.
- Schema subsets are generated from the live registry and prototype-only description overlays.
- Every row stores the contract version, generator/template family, split seed, offered tools, expected call, and source spans where applicable.
- Training serialization contains only the prompt/schema input and Hammer-native expected call; audit metadata stays outside the rendered training text.

### High-value boundary matrix

| Positive intent | Competing intent | Required distinction |
|---|---|---|
| `read` | `yuki_read` | Arbitrary OS path versus Yuki managed filename. |
| `yuki_write` | `yuki_append` | Create/replace complete contents versus preserve then add. |
| `see` | `image` | Inspect existing visual input versus generate new visual output. |
| `search` | `recall` | External web information versus Yuki persistent memory. |
| `search` | `fetch` | Topic/query versus exact URL content. |
| `remember` | `recall` | Store a new fact versus retrieve a stored topic. |
| `weather` | `search`/`fetch` | Current conditions for a place versus research/pages about weather. |
| `read` | `shell` | Read one file directly versus execute a user-supplied command. |

Each boundary needs both directions, negated mentions, paraphrases, explicit commands, implicit requests, preservation cases, and controls where the competitor is mentioned but not intended.

## Training stage

Base checkpoint: `MadeAgents/Hammer2.1-1.5b` from the external disk.

Training must remain one model at a time. Start with LoRA/QLoRA rather than full fine-tuning, preserve the base checkpoint, and version:

- dataset manifest and SHA-256;
- train/validation/hard-dev ID lists;
- schema-description profile;
- tokenizer/chat template;
- adapter configuration and seed;
- every checkpoint evaluated;
- exact native decoding configuration.

Hyperparameters should be selected from validation behavior, not the sacred 450. A small controlled sweep is acceptable; broad blind sweeps are not.

## Gate before the sacred 450

Compare the base Hammer 1.5B and specialized Hammer 1.5B on the exact same validation and hard-dev splits. The candidate advances only if it shows a clear non-regressive gain:

1. higher typed contract exact-call accuracy overall;
2. higher tool selection on ontology boundaries;
3. literal-source exactness near deterministic-label ceiling;
4. schema validity at least as strong as base;
5. malformed and unnecessary rejection rates no worse than base;
6. no major per-tool collapse hidden by the aggregate;
7. improvements survive hard-dev, not only validation;
8. case-level paired flips support a real gain rather than score noise.

Only one checkpoint/configuration is nominated before the frozen 450 is opened.

## Final comparison after the gate

The selected specialized 1.5B will be compared against the frozen references:

| Reference architecture | Frozen official strict exact |
|---|---:|
| Hammer 2.0 7B direct | 81.8% (368/450) |
| Qwen3.8-27B → Hammer 2.1 1.5B | 79.6% (358/450) |
| GPT-OSS-20B direct | 76.2% (343/450) |

The final report must keep two score families separate:

1. Frozen official strict accuracy, for continuity with all historical results.
2. Typed-contract accuracy, using checksum-bound literal references and semantic alternatives.

Success is not merely beating 81.8%. The specialized 1.5B must also retain its practical advantage in latency and memory while showing that its gains come from Yuki-specific routing and argument discipline rather than benchmark leakage.

## Immediate next implementation work

Before data generation:

1. Review and freeze `yuki-argument-contract-v1`.
2. Create the training-record schema and split manifest format.
3. Build deterministic validators for source offsets, composite Yuki payloads, native Hammer output, registry/schema drift, duplication, and sacred-450 overlap.
4. Generate a small 100–200-row pilot across every contract mode.
5. Human-review the pilot before scaling to 6,400.

No model training or frozen-450 inference should begin before those five checks pass.
